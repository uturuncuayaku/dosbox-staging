# Loguru Functionality Walkthrough

This report details how the **Loguru** logging framework is integrated into DOSBox Staging, how its formatting is controlled, and how we can (and cannot) customize it dynamically.

## 1. The Preamble (Prefix) Structure

Every standard log line generated by Loguru is prefixed with a "preamble". The structure and order of this preamble is strictly hardcoded inside the `print_preamble` function in `src/libs/loguru/loguru.cpp`.

The default format is:
`YYYY-MM-DD HH:MM:SS.mmm ( uptime ) [ thread id ] file:line VERBOSITY| message`

> [!NOTE]
> Because this format is baked into `snprintf` calls inside `loguru.cpp`, it is impossible to reorder the fields, strip out the `[` brackets, or arbitrarily rename verbosity levels (like changing `INFO` to `Test Info`) without directly modifying the third-party `loguru.cpp` file.

## 2. Dynamic Configuration (On-The-Fly)

While the *order* and *formatting* of the preamble are hardcoded, Loguru exposes several global boolean flags that allow you to dynamically turn specific fields ON or OFF at runtime.

These globals are defined in `loguru.hpp` and can be toggled anywhere in your code:

```cpp
loguru::g_preamble_date    // Toggles the Date field
loguru::g_preamble_time    // Toggles the Time field
loguru::g_preamble_uptime  // Toggles the Uptime field
loguru::g_preamble_thread  // Toggles the Thread ID field
loguru::g_preamble_file    // Toggles the File/Line number field
loguru::g_preamble_verbose // Toggles the Verbosity (INFO, WARNING, etc.)
loguru::g_preamble_pipe    // Toggles the pipe symbol `|`
```

### Temporary Overrides
You can achieve on-the-fly customization for specific code blocks by saving the state of these globals, modifying them, and then restoring them.

```cpp
// Save current state
bool old_date = loguru::g_preamble_date;
bool old_thread = loguru::g_preamble_thread;

// Modify config for our specific use case
loguru::g_preamble_date = false;
loguru::g_preamble_thread = false;

LOG_DEBUG("This line has no date or thread ID!");

// Restore original state
loguru::g_preamble_date = old_date;
loguru::g_preamble_thread = old_thread;
```

## 3. Disabling the Preamble Entirely

If you need to print a log line without any timestamp or prefix whatsoever (such as when printing a clean visual border like `=====` or `-----`), you have two primary options:

### Option A: Toggle the Master Preamble Flag
Loguru provides a master toggle switch: `loguru::g_preamble`. Setting this to `false` strips the entire prefix.

```cpp
loguru::g_preamble = false;
LOG_DEBUG("==================================");
loguru::g_preamble = true;
```

### Option B: Use RAW Logging
Loguru exposes a macro called `RAW_LOG_F` which bypasses the preamble printing entirely. This is highly useful for multi-line block formatting, although it must be invoked using Loguru's native syntax rather than DOSBox Staging's wrapper macros.

## 4. DOSBox Staging Integration

DOSBox Staging wraps Loguru inside `src/misc/logging.h`. 
For example, the `LOG_DEBUG` macro you are using is defined as:

```cpp
template <typename... Args>
void LOG_DEBUG(const std::string& format, const Args&... args) noexcept
{
	const auto format_green = std::string(loguru::terminal_green()) +
	                          loguru::terminal_bold() + format +
	                          loguru::terminal_reset();

	DLOG_F(INFO, format_green.c_str(), args...);
}
```

> [!TIP]
> This wrapper is what gives your `LOG_DEBUG` traces their distinctive bold green color in the terminal, relying on ANSI escape codes provided by `loguru::terminal_green()`.

## Conclusion

Loguru is an incredibly powerful and thread-safe logging engine. While we cannot rewrite its core layout logic without modifying the underlying source files, its robust system of global toggles gives us plenty of flexibility to manipulate the logs on-the-fly during tests or trace scoping!
